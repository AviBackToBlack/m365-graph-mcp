# m365-graph-mcp — Permission Validation Policy

`endpoints.json` preserves Softeria-style permission metadata for reference, but it is **not normative**.

For each implementation unit:

1. verify the selected endpoint against current official Microsoft Graph documentation;
2. record the least-privileged delegated work/school permission;
3. record any higher permission already known to satisfy the endpoint;
4. test using the actual Graph Explorer-derived bearer;
5. treat 401/403 as a capability/authentication result, not as a reason to broaden scopes automatically.

Important examples already verified during project preparation:

- Listing chat messages currently documents delegated `Chat.Read` as least privileged; do not blindly require the catalog's `ChatMessage.Read`.
- Listing chats accepts `Chat.ReadBasic`, `Chat.Read`, or `Chat.ReadWrite`.
- `calendar/getSchedule` can use `Calendars.ReadBasic`; `Calendars.Read` also satisfies it.
- Microsoft Search `/search/query` permissions depend on the entity types being searched; do not require every permission listed in a broad reference catalog for every call.
- Copilot Retrieval requires both `Files.Read.All` and `Sites.Read.All` for `sharePoint` and `oneDriveBusiness`, and `ExternalItem.Read.All` for `externalItem` (Copilot connectors); see "Copilot Retrieval (SM-14 part C)" below.

Never request broader consent automatically. Missing permissions are reported as a clearly named capability gap for human review.

### SM-10 capability tests (unavailable permissions)

`src/tools/group-capability.test.ts` (mocked Graph, all eight SM-10 tools) mirrors the SM-6 shared-mailbox precedent: a 403 is a `capability_gap` with the "do not broaden scopes automatically" guidance and Graph's status/code in `details`, after exactly one request (no retry, no scope escalation); a 401 is `reauth_required`; a 401/403 on a followed page fails the whole call instead of returning the first page; tokens never leak (even if Graph echoes them, and a batch response echoing the token fails closed). Group-specific boundaries: hidden-membership groups (members 403; `Member.Read.Hidden` is never requested), limited-information `directoryObject` members/owners (`id` + `@odata.type` items survive with and without `select`), and group kinds without a calendar or conversations (400/404 are `graph_error`, never an empty list). The tests assert no undocumented Graph error code and do not replace a live-tenant check.

## Microsoft Search query (SM-14 part B)

`search-query` is `POST /search/query` (v1.0). The server builds exactly one logical request, `{ "requests": [ { "entityTypes", "query": { "queryString" }, "from", "size" } ] }`, with `from` defaulting to 0 and `size` to 25. Nothing else is sent: no `fields`, `aggregations`, `aggregationFilters`, `collapseProperties`, `sortProperties`, `queryTemplate`, `contentSources`, `region`, `enableTopResults`, `queryAlterationOptions`, `resultTemplateOptions`, `sharePointOneDriveOptions`, no raw request object and no caller headers (no `Prefer`). `graph-batch` is GET-only and the tool has no `batchPolicy`, so it is unreachable from batch.

| --- | --- | --- |
| `message` | `Mail.Read` | Own mailbox only (no delegated/shared mailboxes); `total` is the page's result count, not the overall total; Learn: `from` must be 0 on the first page, `size` max 25. |
| `event` | `Calendars.Read` | Own primary calendar; `total` is the page's result count; `size` max 25. |

## Graph Explorer token bridge

The bridge uses a delegated Microsoft Graph bearer obtained through a dedicated browser profile. The MCP server is retrieval-only but the bearer itself may carry broader delegated scopes; **do not** treat this server's catalog as a restriction on any other holder of that token. Do not grant Graph Explorer write scopes for this server unless separately justified.

M365_GRAPH_TENANT_ID is the bridge's required corporate tenant pin. M365_TENANT_ID is an optional, distinct pin for the server's manual mode. Tokens are neither auto-detected nor silently shared between modes. A Graph 401 yields reauth_required; token invalidation is controlled by the browser-side bridge and Microsoft rather than a broker invalidate operation.

Live capability tests must use an authorised tenant and synthetic/redacted evidence. For the shape-only acceptance procedure, see docs/macos-sm15-acceptance.md. The original engineering acceptance transcripts and internal action log are not distributed.

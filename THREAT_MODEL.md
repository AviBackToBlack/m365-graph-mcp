# m365-graph-mcp — Threat Model

Status: security review of the implemented runtime and its documented residual risks. Its controls are independently pinned by source and tests, but some release/publication security checks are not yet complete. The normative product contracts are SECURITY_INVARIANTS.md, ARCHITECTURE.md, TOOL_SURFACE.md, and endpoints.json.

Evidence conventions: file = path under src/; INV = section of SECURITY_INVARIANTS.md; test = pinning test file. Historical D# identifiers identify design choices described here; the private engineering decision log is not part of the public distribution. Status values are mitigated, accepted or open.

## 1. Scope

In scope: the stdio MCP server (`m365-graph-mcp`), its Graph client and 76 catalog tools, its two token sources (`manual`, `bridge`), and the Graph Explorer token bridge (`m365-graph-bridge`: broker socket, dedicated browser profile, CDP pipe, token gate).

Out of scope (not controlled by this code): Claude Desktop and the model, other MCP servers in the same Claude Desktop, Microsoft Entra/Graph server-side enforcement, the Graph Explorer web application, Chrome/Edge internals, macOS itself (Keychain, FileVault, TCC), and the GitHub/npm infrastructure.

Runtime target is macOS with Claude Desktop. Development can be on Windows or Linux; Windows-specific behavior exists only as the dev named-pipe option (`bridge/config.ts`, `bridge/ipc-path.ts`: honored only when `platform === "win32"`, rejected elsewhere) and is not a production path.

## 2. Assets

| # | Asset | Where it lives | Why it matters |
|---|---|---|---|
| A1 | Graph delegated bearer (access token) | bridge process memory (`bridge/capture.ts`); broker response; MCP process memory per request; `M365_GRAPH_ACCESS_TOKEN` in manual mode | Grants whatever scopes the issuing client consented, for the token lifetime. **Not limited to retrieval**: this project's retrieval-only property is a property of the MCP code, not of the bearer (see T9). |
| A2 | M365 content (mail, calendar, Teams, SharePoint, directory, presence) | Graph responses, tool results in MCP process memory and in the MCP channel | Confidential; also untrusted input to the model. By design it is sent to the model provider via Claude Desktop. |
| A3 | Bridge browser profile (`<bridge dir>/profile`) | Disk, bridge dir `0700` (`bridge/browser.ts` `ensureProfileDir`) | A persistent, authenticated corporate browser session (cookies, MSAL/browser state). Stronger asset than A1: it can mint new tokens (T11). |
| A4 | Broker socket (`<bridge dir>/b.sock`, `0600`) | Disk (Unix domain socket) | The only way to obtain A1 from the bridge. |
| A5 | MCP stdio channel | Claude Desktop <-> MCP process | Carries tool calls and A2; stdout is protocol-only. |
| A6 | Catalog / tool surface (`endpoints.json`) | Repo | Defines the capability boundary; its integrity is a security property (T1-T3). |
| A7 | Build and release artifacts | Public source checkout, CI, minimal verified npm package and SBOM | Supply-chain integrity (T25-T27). |

## 3. Actors and adversaries

| Actor | Capability assumed | Notes |
|---|---|---|
| ADV-1 Malicious M365 content / prompt injection | Can place arbitrary text in mail, chats, files, calendar bodies that the model will read | Cannot call tools directly; influences the model only. |
| ADV-2 Other local processes, same macOS user | Run as the same UID: can read the user's files, process environment, connect to the user's sockets, launch Chrome | Includes **other MCP servers** installed in the same Claude Desktop. Inside the `0700` boundary (D43). |
| ADV-3 Other local users on the Mac | Different UID | Blocked by directory/socket permissions. |
| ADV-4 Malicious web page in the bridge browser | Runs in the bridge browser profile (the user can browse anywhere in that window) | Cannot reach the CDP pipe (inherited fd, not a port). |
| ADV-5 Compromised dependency / supply chain | Code execution inside the MCP or bridge process, or in CI | Sees A1 and A2 by construction. |
| ADV-6 Confused / manipulated LLM caller | Chooses tool names and arguments, subject only to schemas | The realistic consequence of ADV-1. |
| ADV-7 Network attacker | MITM / DNS control between the Mac and Microsoft | TLS to `graph.microsoft.com` only. |

## 4. Trust boundaries and data flow

```text
                 (B1) stdio JSON-RPC                       (B2) HTTPS, fixed origin
Claude Desktop <---------------------> m365-graph-mcp ---------------------------> graph.microsoft.com
 (model, user,                          (tools, GraphClient,                          (authoritative
  other MCP servers)                     TokenProvider)                                authorization)
                                              |
                                              | (B3) Unix domain socket, 0700 dir / 0600 sock
                                              |      getToken | status
                                              v
                                       m365-graph-bridge (broker + capture + token gate)
                                              |
                                              | (B4) CDP over inherited pipe fd 3/4 (no port)
                                              v
                                    Chrome/Edge, dedicated --user-data-dir
                                              |
                                              | (B5) browser <-> Microsoft login / Graph Explorer
                                              v
                                    login.microsoftonline.com, developer.microsoft.com, graph.microsoft.com
```

| Boundary | Crossing data | Enforced by |
|---|---|---|
| B1 Claude Desktop <-> MCP | Tool names/arguments in; `{ok,data|error}` envelopes out (A2) | `server.ts`/`registry.ts` strict schemas, `envelope.ts`; no HTTP listener (`index.ts` imports only the stdio transport) |
| B2 MCP <-> Graph | Bearer out; JSON in | `graph/client.ts`, `graph/url.ts` (fixed origin, catalog allowlist, `redirect: "manual"`) |
| B3 MCP <-> broker | Bearer in the response line | Filesystem permissions only (D43); `auth/bridge-token-provider.ts` `verifyEndpoint`, `bridge/broker.ts` |
| B4 bridge <-> browser | CDP commands/events (transient, sensitive) | `bridge/cdp-pipe.ts` fixed method and event allowlists, 8 MiB frame cap |
| B5 browser <-> Microsoft | Interactive login, MFA, Graph Explorer traffic | Browser-owned; the bridge only observes (D42) |

Manual-token mode has no B3-B5: the operator supplies `M365_GRAPH_ACCESS_TOKEN` (`auth/manual-token-provider.ts`).

### 5.2 Authentication material (A1) and the bridge (B3-B5)

| ID | STRIDE | Threat | Boundary | Existing mitigation (verified) | Residual risk | Status |
|---|---|---|---|---|---|---|
| T9 | E/I | The bearer is more powerful than the MCP's retrieval-only code (no `scp` policy): anything holding it can call Graph arbitrarily, including writes if Graph Explorer consented to write scopes | B3 | None on scope content: D44 requires only a non-empty delegated `scp` and no `roles`; scopes are deliberately never inspected for write capability (`bridge/token-gate.ts`). | T10 | I | A same-user local process (ADV-2, incl. any other MCP server in Claude Desktop) connects to the broker and obtains the bearer | B3 | Broker is a Unix domain socket in a `0700` directory (owner/mode verified, symlinks refused, ancestors checked, `0600` socket, `bridge/broker.ts` `ensureRuntimeDir`/`assertSafeAncestors`); never TCP (`bridge/ipc-path.ts`); only `getToken` and token-free `status`, 1 KiB request cap, 16 connections, 5 s idle timeout; the MCP side refuses a socket/dir not owned by the user (`auth/bridge-token-provider.ts` `verifyEndpoint`). ### 5.3 Platform, supply chain and process

| ID | STRIDE | Threat | Boundary | Existing mitigation (verified) | Residual risk | Status |
|---|---|---|---|---|---|---|
| T22 | T | Windows development assumptions leak into the macOS runtime (named pipe, drive paths) | — | `M365_GRAPH_BRIDGE_DEV_PIPE` is honored only on `win32`, validated to `\\.\pipe\<name>`; on other platforms it is a configuration error; production sockets must be absolute POSIX paths under 103 bytes (`bridge/ipc-path.ts`, `bridge/config.ts`); browser paths are fixed macOS locations or an explicit absolute path (`bridge/browser.ts`); POSIX owner/mode checks skipped only on `win32`. Tested with platform overrides (`bridge/config.test.ts`, `bridge/broker.test.ts`) | Windows named pipes carry default Windows ACLs and no `0700` equivalent; dev/test only | mitigated |
| T23 | E | Graph content selects executables, arguments or paths | — | No shell, no `exec`; the only spawn is the browser with `shell: false` and fixed arguments plus a profile path (`bridge/browser.ts`); no tool reads or writes files; M365 content is not persisted by this code (INV); verified by source search (no `child_process` outside `bridge/browser.ts`, no file writes outside the bridge directory management) | The browser executable can be chosen by the operator (`M365_GRAPH_BROWSER_PATH`); an attacker who can set that variable already controls the user's environment | mitigated |
| T24 | S/I | Network attacker (ADV-7): MITM, downgrade, DNS, redirect | B2 | Single fixed `https://graph.microsoft.com` origin asserted before every send (`assertFixedOrigin`); redirects never followed; bearer only sent to that origin; standard TLS validation by Node `fetch`; no telemetry dependency | A compromised or corporate-intercepted trust store defeats TLS for any client. No certificate pinning (not attempted) | accepted |
| T25 | T | Compromised or malicious dependency (ADV-5) | A7 | Two direct runtime dependencies (`@modelcontextprotocol/sdk` 1.32.1, `zod` 4.6.5) pinned exactly; lockfile with integrity hashes; CI uses `npm ci`; GitHub Actions pinned to full commit SHAs with `contents: read` (`.github/workflows/ci.yml`, `.github/workflows/security.yml`). The runtime tree is **~94 production packages** (the SDK pulls `express`, `hono`, `cors`, `ajv` and others); `src/` uses only the SDK's stdio server transport (the HTTP libraries are present but not imported by this code) | CI runs `npm run check` and `npm run build`; SM-16 part B1 adds `.github/workflows/security.yml` (`npm audit --audit-level=high` over all dependencies and digest-pinned OSV-Scanner over `package-lock.json`, on every PR, push to main and weekly) and `.github/dependabot.yml` (weekly npm and GitHub Actions version-update PRs; nothing auto-merges). Residual: the token-output rule is a name heuristic (a token in an innocuously named variable is not caught), and alias tracking is syntactic: for example `x.open`/`x.write` on an unusually named fs namespace, `var ns = require(...)` (the loader rule still flags the `require`), `listen(endpoint)` where a path-named variable holds `{ port, host }`, `h[nameVariable] = v` for the Authorization header, and calls through a returned `createRequire()` function (its creation is flagged). No upstream Semgrep rules are vendored or used (Semgrep Rules License v1.0 forbids redistribution; D55): the rules are project-owned, and broad generic coverage comes from CodeQL at the public gate. Semgrep is defense-in-depth, not equivalent to CodeQL. SM-16 part B4 adds `.github/workflows/package.yml` (see T26). Still **absent**: CodeQL, Dependency Review, GitHub secret scanning and artifact attestations (native, public-repository gate, D53). OSV-Scanner and `npm audit` are independent coverage, not equivalent to GitHub Dependency Review; gitleaks is defense-in-depth, not equivalent to GitHub secret scanning | open (partly addressed by B1: audit, OSV, Dependabot; B2: gitleaks; B3: Semgrep; B4: SBOM and hashes; rest per R6/D51) |

## 6. Cross-cutting findings

**Retrieval-only is enforced by the MCP, not by the token.** All catalog and routing controls (T1-T4) limit what *this process* asks Graph. The bearer served by the bridge is whatever Graph Explorer holds (D44 explicitly does not choose or filter scopes beyond "delegated and non-empty"). Any component that obtains the bearer (T10) is not constrained by the catalog.

**Same-UID is inside the boundary.** `0700` directory + `0600` socket defend against other users and against accidental exposure, not against code running as the user. That includes every other MCP server and Claude Desktop extension on the machine. The broker has no authentication step by design (D43), and the profile (T11) is a larger asset than the bearer. Mitigating this class needs a platform feature (peer credentials, OS keychain handoff, sandboxing), not more application code; none is available in dependency-free Node.

**Bearer lifetime is long.** The bridge held a token with about 86,400 s remaining (D49). Microsoft documents CAE token lifetimes of up to 28 hours, near-real-time critical-event revocation with up to ~15 minutes latency, and no CAE for guests (Microsoft Entra, "Continuous access evaluation", updated 2026-04). It is unconfirmed that this token is CAE-bound.

**Retrieval-token source binding is observation, not proof.** D44 anchors trust in *where* the bearer was seen (bridge-owned Graph Explorer page -> exact Graph origin), not in any signature check. Claims are advisory and fail closed on mismatch; opaque tokens are refused rather than guessed.

**Windows vs macOS.** Everything in the threat table assumes the macOS runtime. Windows exists for development with a fake CDP peer (`bridge/fake-cdp.ts`) and an optional named pipe; neither is production.
